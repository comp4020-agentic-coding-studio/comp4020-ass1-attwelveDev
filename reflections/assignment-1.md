# Reflection

1. The breakthrough that moved my work forward was actually something I added in the early stages of iteration.
In the early stages, I realised I had neither reliable testing nor up-to-date documentation.
So, I asked the agent to keep `PLAN.md` continuously updated with new features, each paired with a verifying check; effectively implementing the test driven development method for this prototype.
The `PLAN.md` serves as documentation of all the features of the website for future maintenance.
Meanwhile, the tests verify the functionality of all new features, reducing the need for manual verification which can be time-consuming, and providing more confidence in the product shipped.
These tests also serve to quickly catch whenever existing features regress upon adding new features.

2. I recognise the potential for agentic coding to speed up my workflows as a software developer.
While I often hear of conversations about how AI will replace software developers, I still believe I have autonomy in shaping design decisions, and steering the overall direction.
By changing the harness, I simply automate many tedious tasks like writing tests and setting standards across the project.
For example, in the process of adding animations, I had to make decisions about modifying the harness, and steering the agent towards my expected implementations.
I realised the agent was failing to deliver because there was no established standard for realism and cohesion.
As a software developer, I still need to be actively aware of these decisions, as they can significantly impact my workflow.
In the past few weeks, I have learnt that 'vibe-coding' is not just spamming AI prompts; it still requires skill, albeit, a different skill set than regular software development, but it is still something I want to continue learning to be a better software developer.
